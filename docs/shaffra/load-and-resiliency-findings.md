# Shaffra — load, resiliency and security findings

Severity: **P0** breaks under normal failure or is exploitable now; **P1**
breaks under load or costs an incident; **P2** debt. Paths are relative to
`shaffra/`. "Fix with" names the module in this repo or the change.

## P0

| Repo | Where | Finding | Fix with |
|------|-------|---------|----------|
| events, all | `shaffra_events/pkg/client.go:221-231` | `Subscribe` acks before the handler runs; messages live in an unbounded in-memory queue. ~114 call sites. Crash, deploy or panic loses them. | `events/natsjs` consumer (explicit ack after handler, bounded workers) |
| events | `client.go:85-88,120` | Broker credentials in the connection URL, logged at Info on every boot | `natsjs.Config` keeps credentials out of the URL; `ConnectedUrlRedacted` |
| events | `client.go:143-159,255-293` | Fixed 20 s `AckWait`, no `InProgress`, `Nak` without delay, `MaxDeliver` on 4 subscriptions; under load queued messages exceed 20 s and are redelivered; no consumer dedups | heartbeats, jittered backoff, `MaxDeliver` + DLQ, `events.Inbox` |
| events | `client.go:176,255` | Worker goroutines have no `recover`; `payload[0].(*entities.Character)` in trainer listeners (`adapters/ws/characters/handler.go:167`) is called from them | `events.Recover` applied by the consumer |
| trainer, robot | `services/ragSource/service.go:66-97`; `services/agents/builder.go:436`; `ragMemory.go:80` | A new `pgxpool` per RAG call or agent build, never closed; pools and health goroutines leak until pgvector hits `max_connections` | one pool per process, injected; `pgxx` presets (phase 3) |
| trainer, support, datalake | `adapters/persistance/bootstrap.go:37` and peers | `sql.DB` with unlimited `MaxOpenConns`; the `DB_MAX_OPEN_CONNS` config field is never applied; no simple protocol for PgBouncer | pool limits now; `pgxx` later |
| support | `adapters/restapi/bootstrap.go:1009`; `crm/leads/deleteTestLeads.go:11-38` | `DELETE /api/testData/leads?mobileNumber=…` has no auth and deletes every CRM lead | remove the route or put it behind admin auth |
